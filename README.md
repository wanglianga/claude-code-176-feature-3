# 县域儿童青少年近视筛查复诊配镜补助平台

围绕**“筛查只是起点”**的理念，把学校年度视力筛查之后的告知、家长确认、医院复诊、处方、配镜、
**合作门店配镜补助发放核验**、补助、半年复查和学校日常干预（座位调整、户外活动、家长提醒、用眼指导）连成**一条完整的健康管理记录**，
并对请假、电话无法接通、导入错误、复诊差异大、自行外配眼镜、补助争议、配镜不适、复查未到场、
**门店核验挂起（处方不一致/参数缺失/付款凭证重复/门店重复提交）、售后差额待结清、配镜适应回访**
等异常情形逐项登记、跟进到**闭环**；补助发放后的**退镜/换片/换架**按实际退款与新费用自动重算追回或补发差额，
供县教体部门与卫健部门核对**真实复诊率**、**干预执行情况**与**补助资金安全**。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts ｜ Spring Boot 3 + Spring Security/JPA ｜ PostgreSQL ｜ Redis（可选，本地自动降级为进程内缓存）。

## 一、一键启动（推荐：Docker Compose）

前置：安装 Docker / Docker Compose。

```bash
cd 176-b
docker compose up -d --build
# 首次构建约 5-10 分钟；启动后访问
#   平台首页：   http://localhost:8080
#   Swagger UI： http://localhost:8080/swagger-ui.html
#   OpenAPI：    http://localhost:8080/v3/api-docs
```

Compose 会启动三个容器：`postgres:16`、`redis:7`、应用（8080，**前端已打进同一个镜像/端口**）。
应用首次启动自动建表并写入演示种子数据（3 片区、4 所学校、10 个角色账号、26 名覆盖各类场景的学生）。

停止：`docker compose down`（保留数据）；`docker compose down -v`（同时清空数据卷）。

> 后端接口文档：全栈项目不强制要求 Swagger，本平台仍内置了 OpenAPI 3 文档与 Swagger UI 便于接口核对。

后端默认 `local` profile：使用 **H2 内存数据库**，Redis 自动降级为进程内缓存，零外部依赖。

```bash
# 后端（会自动加载前端构建产物；若仅做后端开发，见下方前端独立 dev server）
cd backend
mvn spring-boot:run                 # http://localhost:8080 （含内置前端与种子数据）

# 前端独立开发（热更新，自动把 /api 代理到 8080）
cd frontend
npm install
```

如需指向外部 PostgreSQL/Redis：

```bash
java -jar backend/target/vision-platform.jar \
  --spring.profiles.active=postgres \
  --DB_HOST=localhost --DB_USER=vision --DB_PASSWORD=vision123
```

## 四、业务主流程（一个学生的健康管理链）

```
名单导入/既往档案
  └─ 现场筛查（裸眼视力、屈光度、散光、用眼习惯问卷、是否戴镜、复测建议、设备校准编号）
       └─ 学校健康老师复核（确认异常 / 误判排除 / 建议复测）
            └─ 家长告知（短信/电话/APP，电话不通自动累计并登记异常）
                 └─ 家长选择（县医院复诊 / 合作门诊复诊 / 暂缓并填原因）
                      └─ 医院复诊回写（真性近视、散瞳、处方参数、复查周期、补助初判、差异登记）
                           ├─ 配镜登记（合作机构 / 家长自行外配；配镜不适跟踪）
                           ├─ 配镜补助（申请 → 卫健核准 → 发放；争议进入复核）
                           ├─ 周期/半年复查（到期未到场自动催办并登记异常）
                           └─ 学校日常干预（座位调整、户外活动、家长提醒、用眼指导）
```

每一步都会写入该学生的**健康管理时间线**；11 类异常情形自动进入**异常事项台账**，处理后闭环：

| 异常情形 | 触发点 | 闭环方式 |
|---|---|---|
| 筛查请假 | 筛查时勾选“请假未检” | 补检完成后闭环 |
| 家长电话无法接通 | 告知时勾选“本次未接通”（累计次数） | 家长接通并确认后闭环 |
| 批量导入信息错误 | 导入行电话格式错等（软错误不阻断） | 班主任修正信息后闭环 |
| 复诊与筛查差异较大 | 复诊勾选“差异大”并说明 | 卫健核对设备/结果后闭环 |
| 家长自行外配眼镜 | 配镜登记选“自行外配” | 凭证核验、补助核准时闭环 |
| 补助资格有争议 | 卫健标记 DISPUTE | 争议处理、补助发放后闭环 |
| 配镜后不适 | 配镜登记“不适” | 复诊调整后闭环 |
| 半年复查未到场 | 复查登记“未到场”（催办计数） | 学生补做复查后闭环 |
| **门店补助核验挂起** | 处方不一致/参数缺失/付款凭证重复/门店重复提交 | 门店补材料或卫健复核放行/驳回后闭环 |
| **售后差额待结清** | 发放后退镜/换片/换架产生追回或补发差额 | 差额实际追回/补发并登记凭证后闭环 |
| **配镜适应回访中** | 学生反馈头晕/看不清/镜架不合适 | 门店上传调整结果、7 天适应回访确认适应后闭环 |

### 4.1 合作门店配镜补助「发放核验」（本期新增）

学生在合作门店配镜取镜后，门店在**“门店补助核验”**页面一次上传四类材料：

1. **验光处方**（处方号 + 球镜/柱镜/轴位/瞳距）；
2. **镜片实际加工参数**（镜片品类 + 加工球镜/柱镜/轴位/瞳距）；
3. **付款凭证**（发票/收据号 + 影像说明，凭证号全局查重）；
4. **取镜签收**（取镜日期、签收人，签收人须与登记家长一致）。

平台自动做**七项逐项核验**，确认是**同一学生、同一副眼镜**后才允许发放：

| 核验项 | 对照内容 | 不通过情形（一律挂起，不直接发补助） |
|---|---|---|
| ① 同一学生 | 学籍、签收人 vs 登记家长 | 签收人缺失或与登记家长不一致 |
| ② 处方一致性 | 门店处方 vs **最近一次复诊处方**逐项 | 无复诊处方；球镜/柱镜/轴位/瞳距任一不一致或缺项 |
| ③ 镜片参数 | 加工参数完整且按该处方加工 | 球镜/加工瞳距等必填项缺失，或与处方不一致 |
| ④ 家庭资格 | 家长已确认 + 复诊医生初判符合 | 家长未确认，或医生初判不符合补助 |
| ⑤ 付款凭证 | 凭证号全局唯一 | 凭证缺失，或已被其他学生/配镜记录使用（重复凭证） |
| ⑥ 取镜签收 | 已取镜、签收日期、签收人齐全 | 未取镜或缺签收日期/签收人 |
| ⑦ 补助标准/防重 | 费用合法、金额≤标准上限、无在途/已发放单 | **门店重复提交**（已有在途单或已发放补助）、金额缺失 |

- 任一不符 → 核验单**挂起待复核**（红色高亮并登记异常事项），**补助不发放**；门店可**补材料重新提交**，
  或由**卫健部门人工复核放行/驳回**；只有“核验通过待发放”的单据能点“确认发放”，
  发放时系统**二次防重**（该学生存在其他已发放/售后挂接中的单据直接拒绝），确保**不会发两次补助**。
- 县域补助标准上限默认 **300 元/副**（应发 = min(实际配镜费用, 标准上限)），可用环境变量
  `VISION_SUBSIDY_CAP` 调整；发放自动生成/更新补助申请并与该副眼镜、核验单一一绑定。

**发放后售后差额（与原补助连在一起）**：家长退镜、只换片或只换镜架时，门店登记**实际退款**与**新费用**，
平台按 `售后费用基数 = 原费用 − 实际退款 + 新费用`、`重算应补助 = min(售后费用基数, 标准上限)` 自动结算：

- **退镜**（全额退款）→ 重算补助为 0，**应追回**原补助；
- **换片**（旧片折退 + 新片费用）→ 费用上升则**应补发**、下降则**应追回**差额；
- **只换镜架**（镜片继续使用）→ 按折退/新架费用重算，通常**无差额**；
- 差额登记后售后单为“待结清”，核验单置“售后处理中”；差额实际追回/补发并登记凭证后才**结清关闭**，
  原补助、售后单、核验单始终连档可查。

**配镜不适跟踪**：学生反馈**头晕 / 看不清 / 镜架不合适**后，门店须**上传调整结果**（重新对光、调校镜架、
返修镜片等）；必要时门店可建立**复查提醒**。平台保留完整售后记录，并自动安排取镜/调整后 **7 天戴镜适应回访**，
回访确认学生已适应才闭环不适与回访事项，否则继续跟进并提醒复查。

> 仅切换 `postgres` profile（数据源/Redis/方言配置见 `application-postgres.yml`）。

### 可手动复验的最小路径
1. `docker compose up -d --build`（或本地 `mvn spring-boot:run`）→ 打开 http://localhost:8080
2. 用 `screener` 登录 → 现场筛查 → 找“卫兰（待筛查）”录入异常视力；
3. `doctor1` 登录 → 复核与干预 → 确认异常，并登记一条“座位调整”；
4. `teacher1` 登录 → 家长告知确认 → 记录告知 → 家长选择“县医院复诊”；
5. `hospital` 登录 → 复诊处方 → 回写真性近视/处方/6 个月周期/符合补助；
6. `clinic` 登录 → **门店补助核验 → 门店上传材料/提交核验**：选学生，填处方（与复诊一致）、
   镜片加工参数（可点“加工参数同处方”）、付款凭证号、取镜签收人（须与登记家长一致）→ 提交；
7. `health` 登录 → 门店补助核验台账：七项全绿为“通过待发放”，点“确认发放”；
   故意把某个处方度数填错或漏填加工瞳距重提一次，可看到单据红色“挂起待复核”，可“门店补材料”或“复核放行/驳回”；
8. 发放后用“登记退镜/换片/换架”录入实际退款与新费用，查看自动给出的应追回/应补发差额；
   在“配镜不适与适应回访”页签登记头晕/看不清，门店上传调整结果，再完成 7 天适应回访；
9. “复查随访”登记完成复查；回到学生“健康档案”查看完整时间线与“门店核验·售后·回访”页签，
   `edu` 看板观察真实复诊率与核验/售后/回访指标。
