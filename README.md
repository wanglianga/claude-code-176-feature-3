# 县域儿童青少年近视筛查复诊配镜补助平台

围绕**“筛查只是起点”**的理念，把学校年度视力筛查之后的告知、家长确认、医院复诊、处方、配镜、
补助、半年复查和学校日常干预（座位调整、户外活动、家长提醒、用眼指导）连成**一条完整的健康管理记录**，
并对请假、电话无法接通、导入错误、复诊差异大、自行外配眼镜、补助争议、配镜不适、复查未到场
等异常情形逐项登记、跟进到**闭环**，供县教体部门与卫健部门核对**真实复诊率**与**干预执行情况**。

**合作门店配镜补助发放核验**：学生在合作门店配镜后，门店上传处方、镜片参数、付款凭证和取镜签收，
平台对照**最近一次复诊处方、家庭资格、补助标准**逐项自动核验，确认**同一学生、同一副眼镜**后才允许发放；
处方不一致、参数缺失、付款凭证重复、门店重复提交的一律**挂起**，绝不重复发放。
补助发放后家长退镜、换片或只换镜架的，平台按**实际退款与新费用**重算应追回/补发的差额，
售后处理始终与原补助关联；学生反馈头晕、看不清或镜架不合适时，门店上传调整结果，
平台保留售后记录并继续提醒**复查与适应回访**。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts ｜ Spring Boot 3 + Spring Security/JPA ｜ PostgreSQL ｜ Redis（可选，本地自动降级为进程内缓存）。

## 一、一键启动（推荐：Docker Compose）

前置：安装 Docker / Docker Compose。

```bash
cd 176-b
docker compose up -d --build
# 首次构建约 5-10 分钟；启动后访问
#   平台首页：   http://localhost:8080
#   Swagger UI： http://localhost:8080/swagger-ui.html
#   OpenAPI：    http://localhost:8080/v3/api-docs
```

Compose 会启动三个容器：`postgres:16`、`redis:7`、应用（8080，**前端已打进同一个镜像/端口**）。
应用首次启动自动建表并写入演示种子数据（3 片区、4 所学校、11 个角色账号、23 名覆盖各类场景的学生）。

停止：`docker compose down`（保留数据）；`docker compose down -v`（同时清空数据卷）。

> 后端接口文档：全栈项目不强制要求 Swagger，本平台仍内置了 OpenAPI 3 文档与 Swagger UI 便于接口核对。

## 二、本地开发启动（无 Docker / 无外部依赖）

后端默认 `local` profile：使用 **H2 内存数据库**，Redis 自动降级为进程内缓存，零外部依赖。

```bash
# 后端（会自动加载前端构建产物；若仅做后端开发，见下方前端独立 dev server）
cd backend
mvn spring-boot:run                 # http://localhost:8080 （含内置前端与种子数据）

# 前端独立开发（热更新，自动把 /api 代理到 8080）
cd frontend
npm install
npm run dev                         # http://localhost:5173
```

如需指向外部 PostgreSQL/Redis：

```bash
java -jar backend/target/vision-platform.jar \
  --spring.profiles.active=postgres \
  --DB_HOST=localhost --DB_USER=vision --DB_PASSWORD=vision123
```

## 四、业务主流程（一个学生的健康管理链）

```
名单导入/既往档案
  └─ 现场筛查（裸眼视力、屈光度、散光、用眼习惯问卷、是否戴镜、复测建议、设备校准编号）
       └─ 学校健康老师复核（确认异常 / 误判排除 / 建议复测）
            └─ 家长告知（短信/电话/APP，电话不通自动累计并登记异常）
                 └─ 家长选择（县医院复诊 / 合作门诊复诊 / 暂缓并填原因）
                      └─ 医院复诊回写（真性近视、散瞳、处方参数、复查周期、补助初判、差异登记）
                           ├─ 配镜登记（合作机构 / 家长自行外配；配镜不适跟踪）
                           ├─ 配镜补助（申请 → 卫健核准 → 发放；争议进入复核）
                           ├─ 门店发放核验（上传处方/镜片参数/凭证/签收 → 逐项核验 → 挂起或发放；
                           │    退镜/换片/换架差额重算结算；不适反馈 → 门店调整 → 适应回访）
                           ├─ 周期/半年复查（到期未到场自动催办并登记异常）
                           └─ 学校日常干预（座位调整、户外活动、家长提醒、用眼指导）
```

### 门店配镜补助的发放核验与售后（/dispense）

1. **门店上传**：门店就某学生的合作门店配镜记录上传处方（球/柱/轴/瞳距）、镜片参数与费用、
   付款凭证号、取镜签收，平台立即自动逐项核验：
   同一学生 → 同一副眼镜（重复提交拦截）→ 重复发放拦截 → 材料完整 →
   处方与最近一次复诊逐项一致 → 家庭资格（复诊初判符合补助）→ 付款凭证唯一 →
   按补助标准（实收 50%、封顶 300 元）核定应补金额。
2. **挂起与更正**：任一项不通过即挂起并登记异常事项（处方不一致/参数缺失/凭证重复/重复提交），
   补助不予发放；门店更正材料后重新提交，核验通过自动闭环挂起事项。
3. **确认发放**：仅核验通过的单据可发放；同一副眼镜已发放的补助在核验、发放、旧补助申请
   三个通道均被拦截，**不会发两次**。
4. **售后差额**：退镜（应补归零，差额全额追回）、换片/换架（按新费用重算，差额补发或追回），
   售后单与原补助申请关联，卫健确认结算后更新原补助（全额追回标记“补助已追回”）。
5. **不适反馈**：学生反馈头晕/看不清/镜架不合适 → 登记售后并通知门店 → 门店上传调整结果 →
   平台保留售后记录，自动建立 14 天后的**适应回访**提醒，并继续提醒周期复查。

每一步都会写入该学生的**健康管理时间线**；11 类异常情形自动进入**异常事项台账**，处理后闭环：

| 异常情形 | 触发点 | 闭环方式 |
|---|---|---|
| 筛查请假 | 筛查时勾选“请假未检” | 补检完成后闭环 |
| 家长电话无法接通 | 告知时勾选“本次未接通”（累计次数） | 家长接通并确认后闭环 |
| 批量导入信息错误 | 导入行电话格式错等（软错误不阻断） | 班主任修正信息后闭环 |
| 复诊与筛查差异较大 | 复诊勾选“差异大”并说明 | 卫健核对设备/结果后闭环 |
| 家长自行外配眼镜 | 配镜登记选“自行外配” | 凭证核验、补助核准时闭环 |
| 补助资格有争议 | 卫健标记 DISPUTE | 争议处理、补助发放后闭环 |
| 配镜后不适 | 配镜登记“不适”或学生不适反馈 | 复诊调整后闭环 |
| 半年复查未到场 | 复查登记“未到场”（催办计数） | 学生补做复查后闭环 |
| 门店配镜核验挂起 | 处方不一致/参数缺失/凭证重复/重复提交 | 门店更正材料重新核验通过后闭环 |
| 补助售后差额待结算 | 退镜/换片/换架重算出差额 | 卫健确认结算（追回/补发）后闭环 |

## 五、主要页面

- **监管看板**：筛查率、异常率、**真实复诊率（已复诊/筛查异常）**、异常闭环率；各年级近视发展趋势、
  阶段漏斗、片区对比、异常事项分布（含核验挂起/售后差额）、学校真实复诊率与干预执行数排名。
- **学生名单**：按学校/年级/片区/状态/关键字筛选；Excel(.xlsx)/CSV 批量导入（可下载模板）、导入错误修正、手工新增。
- **学生健康档案**：一条时间线串联筛查→告知→复诊→处方→配镜→补助→复查→干预，并分页签展示各类原始记录
  （含“门店核验”页签：核验单逐项结果、售后差额与调整记录）；
  页面内可直接执行 9 类业务操作。
- **发放核验**：核验单台账（通过/挂起/更正重提/确认发放/售后登记/不适反馈）、门店上传材料、
  售后与差额结算台账（结算、上传调整结果）。
- **现场筛查 / 复核与干预 / 家长告知确认 / 复诊处方 / 配镜与补助 / 复查随访 / 异常事项台账**：按角色显示菜单。

### 可手动复验的最小路径
1. `docker compose up -d --build`（或本地 `mvn spring-boot:run`）→ 打开 http://localhost:8080
2. `store` 登录 → 发放核验 → “门店上传核验材料”：选学生与配镜记录，填处方/镜片参数/凭证号/签收 →
   提交后查看“核验明细”逐项 √/× 结果；
3. 故意填与复诊不同的球镜度数、或留空镜片参数/凭证号、或复用他人凭证号 → 核验挂起并进入异常台账；
   更正后“更正重提”→ 通过；
4. `health` 登录 → 发放核验 → 对“核验通过”的单据“确认发放”；再次发放被拦截；
5. 对已发放单据“售后登记”：退镜（全额追回）或换片（填新费用，自动算出差额）→ 售后台账“确认结算”；
6. 对已发放单据“不适反馈”（头晕/看不清/镜架不合适）→ 售后台账“上传调整结果”→
   “复查随访”里出现 14 天后的“适应回访”计划；
7. 回到学生“健康档案 → 门店核验”页签查看逐项核验明细与售后记录，`edu` 看板观察“核验挂起/售后待办”指标。
